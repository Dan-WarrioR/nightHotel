# Night Hotel

Unity 6.3 LTS (`6000.3.28f1`), URP, Windows. Git + Git LFS. Rider (`nightHotel.sln`, regenerated by Unity, not tracked).

## Project layout

All game content lives under `Assets/_Game/`. Only these stay at the `Assets/` root:
- `Plugins/` - third-party code installed as assets (Odin `Sirenix/`). Never put game code here.
- `StreamingAssets/` - FMOD banks, mods, localized audio (must be at the root to work).
- `AddressableAssetsData/` - generated by Addressables.

```
Assets/_Game/
  Content/   Characters, Environment, Nature, Props, UI, UnityAnimations, VFX, Audio, Materials, Shaders, Fonts
  Data/      Settings (URP assets, volume profiles, RainbowFoldersRuleset), Input, Localization, Configs (SO instances)
  Prefabs/   Characters, Environment, Props, UI, VFX, Cameras, Systems
  Scenes/    Boot (build index 0), Core, MainMenu, DevRoom
    Levels/<LevelName>/   <LevelName>.unity + Timelines/, Lighting/ ...
  Scripts/   see assemblies below
  Tests/     EditMode/, PlayMode/
```

Empty folders are tracked only through their `.meta`; Unity 6.3 recreates a missing folder from its `.meta` (same GUID), so no `.gitkeep` is needed. Asmdefs without scripts log "will not be compiled, because it has no scripts" until code is added; that warning is expected.

## Dependency injection (VContainer)

- All services are registered in VContainer `LifetimeScope`s; no static singletons, no `FindObjectOfType`, no service locator calls in gameplay code.
- Scope hierarchy: a project-wide root scope (persistent services: saves, settings, audio, scene loading, game state machine) and child scopes per scene (`Core`, `MainMenu`, levels) for scene-local services. Scope prefabs live in `Prefabs/Systems`.
- Each assembly exposes its registrations through installers (`IInstaller`) so a scope composes them instead of registering types one by one.
- Plain C# classes use constructor injection. MonoBehaviours use `[Inject]` methods (never constructors) and are registered via `RegisterComponent*` or spawned with `IObjectResolver.Instantiate` so they get injected.
- Prefer VContainer entry points (`IStartable`, `ITickable`, `IAsyncStartable`, `IDisposable`) over MonoBehaviour `Update` for non-visual systems.
- Depend on interfaces declared in `Core`; register implementations with `.As<IInterface>()`. Default lifetime is `Singleton` within its scope; use `Transient` only for stateless or per-use objects.
- Async startup work uses UniTask (`IAsyncStartable.StartAsync(CancellationToken)`) and honors the cancellation token.

## Assemblies

| asmdef | Folder | May reference |
|---|---|---|
| `NightHotel.Core.HSM` | `Scripts/Core/HSM` | nothing game-specific |
| `NightHotel.Core` | `Scripts/Core` (incl. `States/`) | HSM, VContainer, UniTask |
| `NightHotel.GameData` | `Scripts/GameData` (ScriptableObject definitions) | Core, Localization, Addressables |
| `NightHotel.Features` | `Scripts/Features/<Feature>/` (AI, Saves, Dialogues...) | Core, HSM, GameData, gameplay packages |
| `NightHotel.ProjectTools` | `Scripts/ProjectTools` | Editor-only, anything |
| `NightHotel.Tests.EditMode` / `.PlayMode` | `Tests/` | everything under test |

- One `Features` assembly for all features; features may reference each other.
- Dependencies point downward only: Core never references GameData or Features.
- Namespaces match folders, root namespace `NightHotel` (e.g. `NightHotel.Features.Dialogues`).
- Adding a package reference to an asmdef uses its assembly name (`PrimeTween.Runtime`, `Unity.Cinemachine`, `VRM10`, `UniTask`, `VContainer`, ...).

## Packages

- DI: VContainer. Async: UniTask (prefer over coroutines and `Task`). Tweens: PrimeTween (not DOTween).
- Inspector: Odin (`Assets/Plugins/Sirenix`). Events: UltEvents 3.1.1, embedded package in `Packages/com.kybernetik.ultevents` (assembly `Kybernetik.UltEvents`, namespace `UltEvents`); prefer it over `UnityEvent`.
- Unity: Addressables, Localization, Cinemachine 3, Behavior, Animation Rigging (IK), Input System, Timeline, Test Framework.
- Characters: UniVRM `com.vrmc.gltf` + `com.vrmc.vrm` (VRM 1.0; loads VRM 0.x files by migration). VRM 0.x package intentionally not installed.
- PrimeTween comes from the npm scoped registry in `Packages/manifest.json`.
- Git packages are pinned by tag; Rainbow Folders 2 has no tags (pinned only by `packages-lock.json`). Its icons are CC BY-NC.
- Planned: FMOD.

## Code style

`.editorconfig` is the source of truth: file-scoped namespaces, `_camelCase` private fields, PascalCase members/constants, `I`-prefixed interfaces, braces always, no column alignment. Do not use `?.` / `??` on `UnityEngine.Object` (bypasses Unity's null check). One MonoBehaviour per file, file named after the class.

## Version control

- Unity YAML assets merge with UnityYAMLMerge (`merge=unityyamlmerge` in `.gitattributes`); each clone must configure the driver (command in the `.gitattributes` header).
- Binaries (textures, models, `.vrm`, audio, FMOD `.bank`, video, fonts, DLLs) go to LFS via `.gitattributes`. Add new binary extensions there before committing such files.
- Always commit an asset together with its `.meta`.

## Driving the Editor (Unity CLI)

The Editor is usually open; drive it with `unity command ... --project-path "E:\Programming\Repos\nightHotel"` instead of editing `.unity`/`.prefab`/`.asset` YAML by hand.
- Move/rename/delete assets only through the AssetDatabase (`unity command asset move` or `script eval`) to keep GUIDs.
- Packages: `unity command package add --name <id|git-url> --confirm true --wait true`. The connection often drops on the domain reload that follows; wait for `unity status` to report `ready` and verify in `Packages/manifest.json` before treating it as a failure.
- `script eval`: pass code via `--file <path.cs>` (inline quoting breaks in PowerShell). Long main-thread work such as `AssetDatabase.ImportPackage` blocks the bridge; schedule it with `EditorApplication.delayCall` and watch `Editor.log`.
- Compile check: `unity recompile`. Tests: `unity command test run --mode EditMode`; PlayMode must run with `--async-tests true`, then read `unity command test status --detail full`.
- Console noise "...com.unity.render-pipelines.universal/Tests/... has no meta file" comes from the URP package, not the project.
